# Saved displays and keyboard control

Open **Connection**, use **Add display**, enter an address in the connection sheet, and pair that display. Choose the target inside Connection or the native menu. The sidebar shows the selected display model/name. Names are local labels; **Save name** does not change the monitor's own name. **Forget connection** clears only the selected display's credentials. An unpaired entry can then be removed while at least one entry remains.

Each display has independent credentials, certificate pins, polling, input association and operation state. An offline display does not block another display. Draft settings reset on target/input changes. Native menus capture their original target and reject actions if the selected display changed while the menu was open. Commands already sent to the original display may finish there; selection never redirects an in-flight operation.

Existing single-display profiles migrate into encrypted `displays.enc` automatically. The original `connection.enc` stays unchanged as a recovery copy. It is no longer the active database; downgrading to an older app will use its older connection state. Do not delete the active catalog to recover a connection you deliberately forgot. Back up the entire application profile before recovery; restore encrypted files only on the same OS account and encryption context. A corrupt catalog fails closed instead of silently overwriting connections. Application identity, executable name, bundle identity and existing profile paths remain stable.

New displays start with read-only setting controls. For Odyssey OLED G8, choose **Odyssey OLED G8 · tested API ranges** in Connection and click **Save controls**. This updates the local profile without pairing again. Initial pairing still authorizes monitor access. This is an explicit profile choice, not automatic hardware certification. Other displays may use their reported input ports and authorized remote commands, but their compatibility is experimental. Sources come from monitor responses; private device titles and raw IDs are not copied into the interface. Unfamiliar port types appear as anonymous Input N entries with their own stable selection targets. Explicit camera sources are excluded. Empty inventories show a notice instead of guessed ports. Unmapped independent input identifiers use two MobileBFF reads with the reduced verification scope shown in the UI.

On **Remote**, choose **Control with keyboard**. Single arrow presses navigate; Enter selects; Backspace sends Back/Return. Escape stops routing locally. Held-key repeats are ignored. Routing stops when leaving Remote, opening connection settings, changing displays, losing focus, hiding the app or disconnecting. Fields, buttons, selectors, volume controls and scrollbars retain normal keys. No global key hook or broadcast is installed.

Open settings (`KEY_MENU`) and Back/Return (`KEY_RETURN`) were observed opening then closing the top-level settings menu on Odyssey OLED G8. Deeper submenu behavior remains unverified. The [upstream remote command reference](https://github.com/xchwarze/samsung-tv-ws-api/blob/master/COMMANDS.md) also maps Back to Return, but does not establish hardware compatibility. Ordinary OK is context-sensitive; it does not emulate the physical joystick quick menu. Exit retains its observed Smart Hub caveat. Remote delivery is reported as command sent, not independently verified menu state.

Use **Display model, shape and speakers** in Connection to save a family label, physical aspect ratio and built-in speaker availability for each display. These are explicit user-confirmed metadata; the known G8 profile supplies defaults. Unsupported or unknown speakers disable the sound controls and show an explanation. **Appearance → Hide sound panel** hides the entire sound area in both the main window and quick controls. These presentation settings do not enable unverified device writes.

Input tiles adapt to the reported inventory: four ports fit across a wide main window and use a 2×2 layout when compact. Larger inventories wrap; quick controls use a bounded scroll area. In **Connection → Input labels and audio return**, optional local names and ARC/eARC badges can be saved without pairing or modifying monitor settings. A badge is reported from an explicit source identifier or supplied by the user; the app never infers eARC from an HDMI number or verifies audio operation from that label.

Compatible MobileBFF services may announce their envelope version; the app uses that version and otherwise retains its existing default. Source switching uses the exact advertised identifier, then two fresh source reads. A resolvable conflicting IP Control input blocks confirmation; an unmappable/ambiguous token uses the explicitly labeled MobileBFF confirmation scope. Other network protocols or devices without compatible IP interfaces remain unsupported.
